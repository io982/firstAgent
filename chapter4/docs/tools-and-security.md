# Инструменты и безопасность

## Реестр инструментов

Инструмент — обычная Python-функция с декоратором `@tool`. Декоратор кладёт
её в глобальный реестр и собирает JSON Schema прямо из сигнатуры: имя функции
становится именем инструмента, первая строка docstring — его описанием
в системном промпте, параметры — полями схемы.

Реестр в курсе один на все главы. Память Главы 3 и поиск Главы 4
регистрируются в том же реестре, что и калькулятор Главы 2, и вызываются
тем же диспетчером.

Отсюда важное следствие: системный промпт и схема ответа собираются
функциями в момент вызова, а не один раз при импорте. Инструменты, которые
регистрируются позже, иначе не попали бы ни в промпт, ни в схему.

## Constrained decoding

Схема ответа агента уходит в Ollama параметром `format`. Модель генерирует
не «текст, похожий на JSON», а токены, разрешённые грамматикой: невалидный
JSON становится физически невозможен, а поле с именем инструмента ограничено
списком реально зарегистрированных имён — выдумать несуществующий инструмент
модель тоже не может.

Отключается переменной окружения `AGENT_STRUCTURED=0`. Тогда работает
запасной разбор свободного текста — он менее надёжен и нужен только для
серверов Ollama старее версии 0.5.

## MCP

Model Context Protocol позволяет подключать чужие инструменты. Клиент в курсе
написан на стандартной библиотеке, общение с сервером идёт по JSON-RPC через
stdin/stdout. Чужие инструменты попадают в тот же общий реестр и становятся
неотличимы от своих. Включается переменной окружения `AGENT_MCP`.

Цена подключения — место в контексте: каждый чужой инструмент добавляет
описание в системный промпт, а промпт и так занимает больше половины окна.

## Защита от инъекций

Прямая инъекция — это когда пользователь пишет «игнорируй предыдущие
инструкции». Запрос проверяется списком паттернов до отправки модели.

Косвенная инъекция опаснее: вредная инструкция приходит не от пользователя,
а из данных — из прочитанного файла, из результата инструмента, из пересказа
диалога, из блока памяти. Пользователь её не писал и не видит.

Защита строится на одном правиле: всё, что пришло извне, — данные, а не
команды. Технически это три вещи:

1. Вывод инструментов, пересказ диалога и блок памяти оборачиваются
   в именованные теги, и системный промпт объявляет содержимое тегов данными.
2. Эти блоки кладутся в сообщение с ролью `user`, а не `system`. Роль
   `system` модель понимает как «инструкция с полномочиями» и подчиняется ей,
   отменяя настоящий промпт.
3. Главное правило повторяется в конце контекста — приём называется
   sandwich defense.

Список паттернов — только первый рубеж, он обходится перефразированием.
Работает именно разделение ролей и тегирование данных.
