# 🔌 Глава 4. Система плагинов: динамический реестр инструментов

## Проблема

В Главе 1 инструменты были **«вшиты»** в код:

| Что менять | Где |
|---|---|
| Имя инструмента | `KNOWN_TOOLS = {...}` |
| Описание для модели | `SYSTEM_PROMPT` |
| Логика вызова | `execute_tool()` через `if/elif` |
| Аргументы | В нескольких местах |

Добавление нового инструмента требовало правки кода в **4 разных местах**. При росте количества инструментов это превращается в хаос.

## Решение

В Главе 4 мы создаём **ToolRegistry** — систему плагинов, которая:

1. 🎯 **Автоматически регистрирует** инструменты через декоратор `@tool`
2. 📋 **Сама генерирует** список известных имён для парсера JSON
3. 📝 **Сама формирует** описание для системного промпта
4. ⚡ **Динамически вызывает** нужную функцию по её имени

## Как это работает

### 1. Декоратор `@tool`

Каждый инструмент — обычная Python-функция с декоратором:

```python
@tool("current_time", "возвращает текущие дату и время")
def current_time() -> str:
    return datetime.now().strftime("%Y-%m-%d %H:%M:%S")
```

### 2. Автоматическая регистрация

При импорте `chapter4.src.tools` все функции с декоратором `@tool` попадают в глобальный реестр `TOOL_REGISTRY`.

### 3. Подмена компонентов агента

Файл `chapter4/agent.py` импортирует ядро из Главы 1 и подменяет три вещи:

```python
from chapter1 import agent as base
from chapter4.src import tools

# 1. Список известных инструментов
base.KNOWN_TOOLS = tools.known_tools()

# 2. Системный промпт (список инструментов генерируется автоматически)
base.SYSTEM_PROMPT = f"""...
{tools.render_tools_for_prompt()}
..."""

# 3. Функция вызова инструментов
base.execute_tool = tools.execute_tool
```

## Новые инструменты в Главе 4

| Инструмент | Что делает |
|---|---|
| `write_file` | Записывает текст в файл (создаёт или перезаписывает) |
| `search_in_directory` | Рекурсивно ищет текст во всех файлах директории |
| `run_command` | Выполняет команды терминала (с подтверждением пользователя) |
| `http_get` | Скачивает страницу по URL и возвращает её текст |
| `current_time` | Возвращает текущие дату и время |

## Как добавить новый инструмент

**5 строк кода — и инструмент доступен агенту:**

```python
from chapter4.src.tools import tool

@tool("weather", "возвращает погоду для города")
def weather(city: str) -> str:
    # Ваша логика здесь
    return f"В городе {city} солнечно, +25°C"
```

Не нужно:
- ~~Менять `KNOWN_TOOLS`~~
- ~~Править `SYSTEM_PROMPT`~~
- ~~Добавлять ветку в `execute_tool`~~

Всё происходит автоматически.

## Безопасность

### Инструмент `run_command`

Выполнение команд терминала — **потенциально опасная операция**. В нашей реализации добавлено обязательное подтверждение пользователя:

```
⚠️  Агент хочет выполнить команду:
   rm -rf /tmp/test

Разрешить? [y/n]: 
```

Если ответ не `y` — команда отменяется.

> ⚠️ **Внимание:** при использовании в продакшене рекомендуется либо полностью отключить `run_command`, либо ограничить список разрешённых команд.

### Инструмент `write_file`

Агент может перезаписывать файлы. В учебных целях это нормально, но для реальных задач стоит добавить:
- Проверку путей (запрет записи в системные директории)
- Логирование всех операций записи
- Подтверждение пользователя (как в `run_command`)
