# 🧠 Глава 5. Долгосрочная память и RAG

## Проблема
В Главе 3 мы добавили память между запросами, но она ограничена 10 сообщениями:

| Ограничение Главы 3 | Последствие |
|---|---|
| Только последние 10 сообщений | Старая информация теряется |
| Память живёт только в рамках сессии | После перезапуска всё забыто |
| Нет поиска по истории | Нельзя найти конкретный факт |
| Линейный рост контекста | Чем длиннее диалог, тем больше токенов |

**Цель Главы 5:** дать агенту **долгосрочную память**, которая:
- Сохраняется между сессиями (перезапуск не стирает данные)
- Позволяет искать информацию по смыслу, а не по точному совпадению
- Не раздувает контекст — в промпт попадает только релевантная информация

## Решение: RAG (Retrieval-Augmented Generation)

```text
Пользователь: "Запомни, что мой проект называется firstAgent"
↓
[remember] → текст превращается в эмбеддинг → сохраняется в ChromaDB
↓
Пользователь (через неделю): "Как называется мой проект?"
↓
[recall] → запрос превращается в эмбеддинг → поиск похожих векторов
↓
Найдено: "Мой проект называется firstAgent"
↓
Агент отвечает, опираясь на найденную информацию
```

Ключевая идея: **мы не храним всю историю в контексте модели**. Вместо этого мы храним её в векторной базе и достаём только то, что нужно для текущего запроса.

## Как это работает

### 1. Эмбеддинги (`src/embeddings.py`)

Эмбеддинг — это числовой вектор, представляющий смысл текста. Похожие по смыслу тексты имеют похожие векторы.

```python
"Как называется мой проект?" → [0.12, -0.45, 0.89, ..., 0.23]
"What is my project name?"   → [0.11, -0.44, 0.88, ..., 0.22]  # близко!
"Который час?"               → [-0.89, 0.12, -0.33, ..., 0.67]  # далеко
```

Мы используем модель `nomic-embed-text` через Ollama API:

```python
response = requests.post(
    f"{OLLAMA_BASE}/api/embeddings",
    json={"model": "nomic-embed-text", "prompt": text}
)
embedding = response.json()["embedding"]
```

### 2. Векторная база (`src/vectorstore.py`)

ChromaDB хранит документы вместе с их эмбеддингами и позволяет искать по косинусному сходству:

```python
client = chromadb.PersistentClient(path="./chroma_db")
collection = client.get_or_create_collection(
    name="agent_memory",
    metadata={"hnsw:space": "cosine"}
)
```

> ⚠️ **Важно:** используется новый API `PersistentClient`. Старый API
> с `Settings(chroma_db_impl="duckdb+parquet")` удалён в ChromaDB 0.4+.

### 3. Инструменты (`src/tools.py`)

| Инструмент | Назначение |
|---|---|
| `remember` | Сохраняет факт в векторную базу |
| `recall` | Ищет информацию по смысловому запросу |
| `list_memory` | Показывает все сохранённые записи |

Все три инструмента зарегистрированы через декоратор `@tool` из Главы 4 —
ничего нового в реестре менять не нужно.

## Инструменты Главы 5 подробно

### remember — сохранить в память

```python
@chapter4_tools.tool("remember", "сохраняет важную информацию в долгосрочную память...")
def remember(content: str = "", category: str = "general", **kwargs) -> str:
```

**Защитные механизмы:**
- **Fallback для выдуманных параметров** (`**kwargs`) — если модель передаст `key`/`value` вместо `content`, мы соберём текст из kwargs
- **Дедупликация** — перед сохранением ищем похожую запись. Если косинусное расстояние < 0.1, это дубль и мы не сохраняем повторно
- **Валидация** — если content пустой, возвращаем понятную подсказку модели

### recall — найти в памяти

```python
@chapter4_tools.tool("recall", "ищет информацию в долгосрочной памяти...")
def recall(query: str, max_results: int = 3) -> str:
```

**Защитные механизмы:**
- **Проверка пустого query** — ChromaDB падает на пустом запросе, поэтому возвращаем понятную ошибку
- **Уровни уверенности** — по косинусному расстоянию: < 0.3 высокая, < 0.5 средняя, иначе низкая

### list_memory — показать всё

```python
@chapter4_tools.tool("list_memory", "показывает ВСЕ сохранённые документы...")
def list_memory(limit: int = 10) -> str:
```

Возвращает **полный текст** записей (без обрезки), чтобы модель не пыталась "уточнить" обрезанный текст повторным вызовом recall.

## ⚠️ Особенности маленьких моделей (3B) — КЛЮЧЕВОЙ РАЗДЕЛ

Мы прошли через несколько итераций отладки, прежде чем агент заработал стабильно. Все проблемы были связаны с особенностями модели 3B. Вот что мы выяснили:

### 1. Few-shot примеры работают лучше абстрактных правил

Модель 3B плохо следует длинным спискам правил. Но отлично копирует конкретные примеры.

```text
❌ Плохо (модель игнорирует):
"КРИТИЧЕСКИ ВАЖНО: После получения результатов от list_memory ты ОБЯЗАН
пересказать ВСЕ записи пользователю. НЕ пропускай записи..."

✅ Хорошо (модель следует):
Пример:
User: Покажи, что ты помнишь
Assistant: {"name": "list_memory", "arguments": {}}
User: Observation from list_memory: Найдено 2 записей...
Assistant: Вот что я помню:
1. [general] Мой проект называется firstAgent
2. [general] Меня зовут Владимир
```

**Эмпирическое правило: для моделей до 7B — 1 пример работает лучше, чем 5 правил.**

### 2. Агрессивные формулировки вызывают откат к базовому поведению

Когда мы добавили в промпт формулировки «КРИТИЧЕСКИ ВАЖНО», «ты ОБЯЗАН», «НИКОГДА», модель 3B **перегрузилась** и откатилась к базовому safety-поведению:

```text
Вы > Покажи, что ты помнишь
🤖 Агент > Извините, но я не могу показать вам информацию из моей
долгосрочной памяти. Это ограничение установлено для безопасности
и конфиденциальности.
```

Модель "вспомнила", что она обучена не раскрывать "внутреннюю память",
и проигнорировала системный промпт. Чем жёстче мы давили, тем сильнее
модель сопротивлялась.

**Решение:** спокойные формулировки + явное снятие ограничений:

```text
Показывать сохранённые записи — это нормальная разрешённая операция.
Ограничений безопасности на это НЕТ.
```

### 3. Модель выдумывает параметры инструментов

Если в промпте указано только имя и описание инструмента, модель может придумать собственные параметры:

```text
Модель вызывает: {"name": "remember", "arguments": {"key": "project_name", "value": "firstAgent"}}
Функция ожидает: remember(content: str, category: str)
Результат: ошибка "missing required argument: content" × 8 итераций
```

**Решение (из Главы 4):** автоматически извлекать сигнатуру функции через `inspect.signature` и добавлять параметры в промпт:

```text
remember — сохраняет важную информацию
Параметры: content (string, обязательно), category (string, по умолчанию: 'general')
```

### 4. Модель склонна переводить на английский

Несмотря на инструкцию "сохраняй на языке пользователя", модель 3B часто переводит текст:

```text
Пользователь: Запомни, что мой проект называется firstAgent
Модель сохранила: "my project is called firstAgent..."
```

Это не критично для поиска (эмбеддинги мультиязычные), но стоит добавить
пример с русским контентом в промпт.

### 5. Итоговая таблица: что работает с моделью 3B

| Приём | Эффективность |
|---|---|
| Few-shot примеры в промпте | ⭐⭐⭐⭐⭐ |
| Короткие спокойные правила | ⭐⭐⭐⭐ |
| Явное снятие ложных ограничений безопасности | ⭐⭐⭐⭐ |
| Сигнатура функций в описании инструментов | ⭐⭐⭐⭐ |
| Агрессивные запреты («НИКОГДА», «ОБЯЗАН») | ⭐ (вредно!) |
| Длинные списки абстрактных правил | ⭐ (вредно!) |
